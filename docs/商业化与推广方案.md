# LabHub · 商业化与推广方案

> 更新日期：2026-09-10  
> 目标：在**不公开源码**的前提下，尽快验证付费、看到收益；优先速度，不优先完美架构。

---

## 1. 结论（先看这三段）

**产品形态**：本机多仓库控制中枢（闭源安装包）+ 官方 LabHub Cloud（账号 / 项目额度 / AI 配额）。属于「本地工具 + 云端增值」的半 SaaS，不是纯网页 SaaS。

**最快见钱的路径**：  
闭源分发 → 强制登录官方 Cloud → 免费额度用完 → 卖「项目扩容」或「AI 加油包」（先只做一个付费点）。

**两周成功标准**：  
≥ 20 人注册试用；其中 ≥ 2～3 人产生付费（哪怕先用个人收款码 + 人工改额度）。

---

## 2. 为什么这样定位

### 2.1 为什么不靠开源获客

若本机端 + Cloud 全部开源，用户可自建 Cloud、自备 DeepSeek Key、改大配额，从而绕过付费。  
当前阶段目标是**尽快收到钱、验证愿付费**，因此：

- 本机 LabHub：**闭源分发**（安装包 / 绿色版）
- Cloud 与计费能力：**只连官方服务器**
- 卖的是「省事的服务与额度」，不是源码

### 2.2 为什么用户愿意付钱

目标用户：一人或小团队要同时管多个 Git 仓库（独立开发者、外包、实验室、工作室）。

痛点与付费动机：

| 痛点 | LabHub 价值 | 可收费点 |
|------|-------------|----------|
| 多仓目录乱、终端多、启停麻烦 | 一处登记、分模式启停、看日志 | 项目管理额度 |
| 新接手项目看不懂 | Cloud AI 出《项目分析总结》 | AI 月配额 / 加油包 |
| 换机器丢清单 | 登录后同步云端清单 | 账号与云同步（含在套餐内） |

### 2.3 收费卡在哪（产品侧已具备）

| 能力 | 现状 | 商业化用法 |
|------|------|------------|
| 手机号注册 / 登录 | 已有 | 强制登录后才能管项目 |
| 默认项目额度（如 3 个） | 已有 | 免费层上限；第 4 个起引导付费 |
| 个人邀请码双边 +1 | 已有 | 拉新；不替代付费主路径 |
| AI 月配额 | 已有 | 免费少量；用尽卖加油包或升级 |
| DeepSeek Key | 仅 Cloud | 用户无法在本机白嫖官方模型 |

## 3. 商业模式（MVP）

### 3.1 原则

1. **先做一个付费点**，跑通「试用 → 付费 → 到账 → 开通」。  
2. 支付可先人工，自动化后置。  
3. 套餐宁少勿多，文案一句话说清。

### 3.2 首发套餐（系统内支付）

| 套餐 | 月付 | 年付 | 项目数 | AI/月 | 说明 |
|------|------|------|--------|-------|------|
| 免费版 | ¥0 | — | 3 | 5 | 试用；含云同步与多端启停 |
| 基础版 | ¥9.9 | ¥99 | 10 | 30 | 独立开发者主推 |
| 专业版 | ¥29 | ¥288 | 30 | 100 | 小团队；含优先支持 |
| AI 加油包 | ¥9.9 / 50 次 | — | — | +50 | 不换套餐，只加次数 |

控制台「套餐」弹窗可对比权限、选择月付/年付，**系统内下单并支付开通**（开发默认 `PAYMENT_MODE=mock` 模拟支付即时生效；正式渠道可后续接入）。

### 3.3 暂缓的产品（避免拖慢收钱）

- 团队席位、权限、审计  
- 完整微信商户 / 发票中台（mock 跑通后再接）  
- 纯云端托管代码 / 在线 IDE  
- 开源版引流双轨（等付费验证后再议）

### 3.4 收款与履约

1. 用户在控制台选择套餐 → 创建订单 → 支付（mock 立即开通）。  
2. Cloud 写入 `plan_id` / `plan_expires_at` / `project_limit`，AI 配额按套餐生效。  
3. 可降级到免费版；邀请码加成的项目位在换档时保留。  
4. `PAYMENT_MODE=live` 时预留真实支付（尚未接渠道会返回提示）。

## 4. 产品交付与防白嫖（闭源推广前提）

### 4.1 用户拿到的是什么

- Windows 安装包或绿色 zip（内含本机 server + client）  
- 打开即用控制台；**必须登录官方 Cloud** 才能添加/管理项目  
- `cloudUrl` 指向你们的正式/测试 Cloud，不提供「填自己 Cloud」的普通入口

### 4.2 必须守住的边界

| 要做 | 不要做 |
|------|--------|
| 二进制 / 安装包分发 | 公开完整 Git 仓（含 Cloud） |
| 官方 Cloud 持有模型与短信密钥 | 在客户端暴露 DeepSeek Key |
| 免费额度写进服务端校验 | 仅前端隐藏「添加仓库」按钮 |
| 服务条款写明：禁止逆向商用破解额度 | 指望君子协议代替服务端限额 |

### 4.3 与「二开绕过付费」的关系

不公开源码 ≠ 绝对无法破解，但大幅提高成本。  
真正收费靠：**官方 Cloud 的额度校验 + 模型与短信成本集中在你侧**。  
即使有人自建类似工具，也拿不到你的运营品牌、更新与官方 AI 配额服务——卖的是持续服务，不是一次性软件拷贝。

## 5. 两周冲刺计划（尽快看到收益）

### 第 0～2 天：可卖、可装

| 任务 | 产出 |
|------|------|
| 打安装包 / 绿色版 | 落地页可下载 |
| 确认强制登录 + 额度拦截文案 | 第 4 个项目、AI 用尽时有明确升级提示 |
| 定首发套餐文案 | 例如：「基础版 ¥39/月 · 10 个项目 · 20 次 AI」 |
| 准备收款方式 | 收款码 + 开通话术（用户发手机号） |
| Cloud 可改额度 | 文档化：如何给某用户加 `project_limit` |

### 第 3～7 天：获客与试用

| 任务 | 产出 |
|------|------|
| 做 1 条 45～90 秒演示视频 | 多仓添加 → 启停 → 日志 →（可选）AI 总结 |
| 上线一页落地页 | 下载 + 注册说明 + 价格 + 联系付费 |
| 发到 3～5 个渠道 | 见下文「推广方案」 |
| 建种子用户表 | 20 人目标：微信/手机号、是否活跃、卡点反馈 |

### 第 8～14 天：逼单与复盘

| 任务 | 产出 |
|------|------|
| 对额度将满 / 已满用户私聊 | 发优惠或首月价（如首月 ¥19） |
| 完成至少 2 笔付费开通 | 验证「钱 → 改额度 → 用户满意」闭环 |
| 复盘 | 哪个渠道来人、卡在哪一步、文案是否清晰 |

**两周结束后决策**：

- 有付费 → 加固安装包、接自动支付、考虑年费  
- 仅注册无付费 → 检查价值是否讲清、免费是否过宽、目标用户是否找错  
- 几乎无人下载 → 先改获客与演示，不急着加功能

## 6. 推广方案（详细）

### 6.1 推广总策略

**一句话**：用「多仓库一键启停」场景获客，用「免费 3 个项目」降低门槛，用「第 4 个项目 / AI 用尽」转化付费。

不靠开源 Star，靠：

1. **可感知的演示**（视频 / GIF）  
2. **低摩擦安装**（下载即用）  
3. **精准人群出没地**（开发者与小团队）  
4. **一对一跟进种子用户**（闭源早期转化率靠私域）

### 6.2 目标用户画像（写进所有文案）

**主画像**：同时维护 ≥ 3 个 Git 项目的个人开发者或 2～5 人小团队。  

**场景举例**：

- 自己有 SaaS + 几个客户项目，每天开一堆终端  
- 实验室 / 课程多仓库，助教要帮同学起服务  
- 外包接多个仓，要快速摸清项目结构（AI 总结加分）

**非优先**：只要单仓的纯前端爱好者；要「完全开源可自建」的用户（与闭源收费冲突，可礼貌说明商业版定位）。

### 6.3 核心信息（对外统一口径）

| 层级 | 文案示例 |
|------|----------|
| 标题 | LabHub：本机多仓库启停与日志中枢 |
| 副标题 | 一个控制台管多个 Git 项目；登录后同步清单，支持 AI 项目分析 |
| 免费承诺 | 注册即用，默认可管理 3 个项目 |
| 付费理由 | 项目多了升级额度；AI 分析按月配额，用完可加油或升级 |
| 信任 | 代码在你本机，云端只存清单与账号，不上传源码 |

### 6.4 内容资产（最少集）

1. **演示视频（必须）**  
   - 时长：45～90 秒  
   - 结构：痛点（多文件夹乱）→ 添加 2 个仓库 → 启动看日志 → 点题「第三个、第四个怎么管」→ 结尾 CTA（下载 / 评论区领）  
2. **落地页（必须）**  
   - 区块：价值主张 → 演示嵌入 → 下载按钮 → 价格 → 常见问题 → 付费联系方式  
3. **图文长帖 1 篇（建议）**  
   - 标题示例：《我把 5 个客户仓库塞进一个控制台之后》  
4. **FAQ 短答**  
   - 是否开源？不开放完整源码，提供安装包与官方云服务。  
   - 代码会上传吗？不会；云端是清单与账号。  
   - 没有 DeepSeek Key 能否用？能，登录后走官方配额。

### 6.5 渠道清单与打法

#### （1）即时见效：开发者社区发帖

| 渠道 | 打法 | 注意 |
|------|------|------|
| V2EX | 「分享创造」类：讲场景 + 演示 GIF + 下载，标明商业工具与免费额度 | 避免硬广口吻；诚实说收费点 |
| 即刻 | 独立开发者圈子：日更进展 + 演示，引导私信领下载 | 重互动，少刷屏 |
| 即友 / 小红书（可选） | 偏「效率工具」封面：多终端对比图 | 标题场景化 |
| 微信技术群 / 同学群 / 实验室群 | 直接发安装包 + 求 5 人试用换一周优先支持 | 种子用户主战场 |

**发帖结构模板**：

1. 我是谁、我有什么问题（多仓启停）  
2. 我做了什么（LabHub 一句话）  
3. 演示（视频 / GIF）  
4. 免费怎么用（3 项目）  
5. 收费怎么说（一句话）  
6. 下载 / 联系方式  

#### （2）内容平台：做搜索与转发

| 渠道 | 内容 | 频率 |
|------|------|------|
| B 站 | 同一演示视频加长版（3～5 分钟教程：安装 → 登录 → 添加仓库） | 首发 1 条，有反馈再更 |
| 公众号 / 知乎 | 一篇深度：多仓库工作流对比「文件夹 + 终端」 | 1 篇即可 |
| 短视频（抖音 / 视频号） | 15～30 秒砍掉细节，只留「一键启动对比」 | 可选 |

#### （3）私域转化：把访客变成付费

1. 所有下载引导加企业微信 / 个人微信「LabHub 试用」。  
2. 注册后 24 小时内：问是否装上、卡在哪。  
3. 已添加 2 个项目的用户：提示「第 3 个免费，第 4 个需升级」。  
4. 额度用尽用户：发价目 + 首月优惠，付款后当天开通。  
5. 建立简单表格：渠道来源、注册日、项目数、是否付费、备注。

#### （4）邀请码：辅助拉新，不替代付费

- 每位用户有个人邀请码；好友注册双方额度 +1。  
- 推广话术：「邀 1 人各 +1 项目，仍不够再升级基础版」。  
- 防止刷邀请：服务端已有注册校验；可后续加设备/频控。  
- **不要**指望邀请 alone 带来收入；它降低获客成本，主收入仍是扩容订阅。

### 6.6 推广节奏（示例周历）

| 日 | 动作 |
|----|------|
| 周一 | 发 B 站教程 + 落地页上线 |
| 周二 | V2EX / 即刻发帖，回复所有评论 |
| 周三 | 私聊已下载未注册用户 |
| 周四 | 再发一则短演示到 2 个社群 |
| 周五 | 统计漏斗；给接近额度用户发升级说明 |
| 周末 | 根据反馈改落地页一句主标题；预约下周 3 个深度访谈 |

### 6.7 转化漏斗与指标

```text
曝光（帖子/视频）
  → 落地页访问
    → 下载安装
      → 注册登录
        → 添加第 1 个项目
          → 接近 / 达到免费上限
            → 咨询付费
              → 付款开通
```

| 阶段 | 两周参考目标 | 若过低则优先改什么 |
|------|----------------|-------------------|
| 落地页访问 | ≥ 200 | 渠道是否发对、标题是否吸引 |
| 下载 | ≥ 50 | 下载按钮是否显眼、是否要登录墙过早 |
| 注册 | ≥ 20 | 短信/验证码是否麻烦；开发环境是否好用 |
| 添加项目 | ≥ 10 | 添加流程、Git 地址说明 |
| 付费意向 | ≥ 5 | 价值是否讲清、免费是否过宽 |
| 成交 | ≥ 2 | 价格、开通速度、信任（收款方式） |

### 6.8 定价与促销话术（可直接用）

**标准价**：基础版 ¥39/月，项目额度 10，AI 20 次/月。  

**首月活动（仅种子期）**：前 30 名付费用户 **首月 ¥19**，次月恢复 ¥39；或年付 ¥399 送 2 个月。  

**异议处理**：

| 用户说 | 回应要点 |
|--------|----------|
| 为什么不开源？ | 云端账号与 AI 是持续成本；安装包保证体验一致；代码仍在你本机。 |
| 太贵了 | 对比你为多仓浪费的时间；可先首月优惠；或先邀请好友各 +1。 |
| 我自己用脚本就行 | 可以；LabHub 卖的是现成控制台 + 云清单 + AI，省搭建时间。 |
| 能不能只买 AI？ | 可提供加油包；但多仓管理建议直接基础版更划算。 |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 有人逆向改客户端 | 额度以 Cloud 校验为准；关键接口鉴权 |
| 免费用户只占 3 个名额不付费 | 正常；用 AI 与年费体验拉动；关注「差 1 个名额」人群 |
| 短信 / AI 成本被刷 | 注册与发短信限流；AI 严格月配额；异常账号停用 |
| 闭源导致信任不足 | 明确「不上传源码」；提供可验证的隐私说明；种子用户口碑 |
| 两周 0 付费 | 访谈 5 人：是不需要、不信任，还是没看懂；再调价格或免费额度 |

## 10. 相关仓库说明（实现侧）

| 部分 | 路径 / 说明 |
|------|-------------|
| 本机控制台与 API | `client/`、`server/`（分发为安装包，不宜整仓公开） |
| Cloud 账号与额度 | `services/cloud/`（PostgreSQL；`DATABASE_URL`；勿提交真实密钥） |
| 公开 Cloud 地址 | `config/public.json` → `cloudUrl` |
| 本机数据 | `data/`（清单与登录态）；代码在 `projects/` |

本文描述的是**商业与推广策略**；具体支付自动化、安装包流水线可在验证付费后再开独立技术任务。
