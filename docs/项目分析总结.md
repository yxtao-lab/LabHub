## 1. 一句话定位

LabHub 是本机**多 Git 仓库控制中枢**：按地址浅克隆/挂载项目，按启动模式分端启停与看日志，经 Cloud 做手机号登录、清单同步、套餐额度与 AI 项目分析；子项目仍用各自 `origin` 提交推送。

## 2. 项目概览

| 项 | 内容 |
|---|---|
| 类型 | pnpm workspace 全栈（本机 API + Vue 控制台 + Electron 壳 + Cloud 服务） |
| 主要语言 | TypeScript |
| 包管理器 | **pnpm**（`packageManager: pnpm@10.30.1`，`pnpm-lock.yaml`） |
| 安装依赖 | `pnpm install` |
| 默认启动 | `pnpm dev`（server `:8790` + client `:5177` + cloud `:8780` + Electron） |
| 当前分支 / 版本线索 | `main`；根包 `0.1.0` |
| 许可证 | 未在仓库体现 |

### 2.1 目标与范围

- 要解决的问题：在一台机器上统管多个独立 Git 项目，统一启停/日志/分析入口，避免把「中枢」嵌进某个业务仓内部。
- 明确不做的事：不替代子项目自己的 git 远程；Cloud **只存清单元数据，不上传源码**；发给用户的是 Electron 安装包，Cloud 只部署在维护者服务器；`services/analysis-relay` 为遗留服务，默认不随 `pnpm dev` 启动。

### 2.2 使用者与场景

- 目标用户：本机同时维护多仓的开发者；安装包终端用户（登录后管理本机克隆）；Cloud 维护者（部署账号/支付/AI）。
- 典型场景：登记仓库 → 多端启动/构建/自定义命令 → 看日志与运行地址 → 读 AI/启发式分析总结 → 换机后按云端清单恢复克隆。

## 3. 我能用这个项目做什么

> 本节回答：作为使用者，跑起来之后能得到什么结果。每条写「可以……从而……」。

| # | 我可以… | 得到的结果 | 依据（功能/路由/脚本） |
|---|---|---|---|
| 1 | 粘贴 GitHub/Gitee 地址添加仓库 | 浅克隆到 `projects/<id>/` 并写入本机清单 | `POST /api/projects`、`projects-service.ts` |
| 2 | 挂载已有本地目录（不重复克隆） | 同一控制台管理绝对路径项目 | `addProject` / 控制台「添加仓库」的本地路径 |
| 3 | 按「启动模式」分端启停，并可改运行端口 | 多进程并行、各有 PID/状态/日志与探测 URL | `startProfiles`、`runPort`、`POST .../start\|stop` |
| 4 | 安装依赖、按构建目标 build、跑自定义命令 | 在控制台完成装包/构建/临时 shell | `POST .../install`、`.../build`、`.../run`、`custom-commands` |
| 5 | 手机号注册/登录（密码或验证码），并用邀请码加额度 | 账号绑定本机清单；默认可管 3 个项目 | Cloud `/v1/auth/*`、本机 `/api/auth/*` |
| 6 | 首次托管时走 Cloud AI 分析（有配额） | 得到各仓 `docs/项目分析总结.md`；Key 只在 Cloud | `POST /v1/analyze`、本地 `/api/projects/:id/analysis*` |
| 7 | 在控制台做清单同步、从云端恢复缺失仓、Git 提交/stash/合并/切分支 | 换机可恢复元数据并再浅克隆；日常 Git 不必离开控制台 | `/api/auth/*catalog*`、`/restore*`、`.../commit\|stash\|merge\|checkout` |
| 8 | 购买/切换套餐（开发为 mock 支付）或打 Windows 安装包 | 提高项目位与 AI 次数；把桌面端发给用户 | `/api/billing/*`、`pnpm package:win`、`electron-builder.yml` |

### 3.1 适合谁用 / 不适合做什么

- 适合：本机同时维护多个实验/客户仓；需要「多端分模式」启停与统一日志；需要云端账号与额度控制。
- 不适合 / 未实现：把本机 API 暴露到公网（`startCommand` 等价任意 shell）；真实支付渠道（`PAYMENT_MODE=live` 仅预留）；用 Cloud 存源码或替代各仓 CI。

### 3.2 与周边系统如何配合

- 被管项目落在 `projects/`（gitignore）或绝对路径；各自独立 `.git`，`git push origin` 仍回源仓库。
- 本机数据：`data/projects.json`、登录态等（gitignore）；安装包默认数据根见 Electron（`%LOCALAPPDATA%\LabHubData`，可由安装时指针/注册表覆盖）。
- Cloud 公网地址写在可公开的 `config/public.json` 的 `cloudUrl`（可用环境变量 `LABHUB_CLOUD_URL` 覆盖）。当前仓库值为 `https://labhubcloud.yxtao.site`；本地一体开发时 `pnpm dev` 仍会起本机 Cloud `:8780`，可用 `LABHUB_CLOUD_URL=http://127.0.0.1:8780` 覆盖。
- Cursor 工作区：`labhub.code-workspace` 多为根工作区 + 各托管仓多根；`server` 启动时会尝试同步该文件。
- 当前本机 `projects/` 可见托管项：`douxing`、`edgetunnel`、`ezshell`、`freellmapi`、`multiuserclaw`、`navigation`、`official-website`、`safetymanagement`、`zj-steel-pipe`，以及指向外部目录的 `zhonglao-project` 符号链接。

## 4. 具体实施步骤

> 每个场景可照做：前置 → 安装配置 → 启动 → 验证。命令以锁文件为准，使用 **pnpm**。

### 场景 A：本地跑通控制台（一体开发）

1. 前置：Node.js ≥ 20.18；本机已装 Git；已安装并启动 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Cloud 依赖 Postgres `:5433`）。
2. 安装：
   ```bash
   cd E:\Desktop\TYX\AI\labhub
   corepack prepare pnpm@10.30.1 --activate
   pnpm install
   ```
3. 启动（会自动补 `services/cloud/.env`、`docker compose` 拉起 Postgres，并并发起 server/client/cloud/Electron）：
   ```bash
   pnpm dev
   ```
4. 验证：
   - 浏览器或 Electron 打开 http://127.0.0.1:5177
   - `curl http://127.0.0.1:8790/api/health` 应返回 `"ok":true`
   - Cloud：`curl http://127.0.0.1:8780/health`
5. 开发账号（`SMS_PROVIDER=dev`）：手机号 `13800138000` / 密码 `labhub123`；短信固定码默认见 Cloud `.env.example` 的 `SMS_DEV_CODE=123456`。

### 场景 B：添加一个远程仓库并按模式启动

1. 前置：已完成场景 A，且已登录（项目 API 需本机登录态）。
2. 控制台点「添加仓库」，或：
   ```bash
   curl -X POST http://127.0.0.1:8790/api/projects \
     -H "Content-Type: application/json" \
     -H "Cookie: <本机登录后的会话>" \
     -d "{\"repoUrl\":\"https://github.com/你的账号/某项目.git\",\"startCommand\":\"pnpm run dev\"}"
   ```
   （控制台操作更省事；curl 需带上登录后的会话信息。）
3. 在项目卡片选择某个启动模式 →「启动」；需要时在模式上配置 `runPort` 避免端口冲突。
4. 验证：状态为 running；日志面板有输出；若探测到 URL，可一键打开。
5. 在源仓目录提交仍推回该仓远端：
   ```bash
   cd projects/某项目
   git add .
   git commit -m "feat(scope): 中文概述"
   git push origin HEAD
   ```

### 场景 C：单独部署 / 发布 Cloud（维护者）

1. 前置：服务器有 Docker、Node、PM2；已配置 `services/cloud/.env`（必填 `JWT_SECRET`、`DATABASE_URL`；生产还需 `DEEPSEEK_API_KEY`、阿里云短信相关变量）。
2. 仓库根执行：
   ```bash
   pnpm release
   ```
3. 或推送 `services/cloud/**` 等到 `main`，由 GitHub Actions **Release Cloud** 经 SSH/`rsync` 同步并执行 `pnpm release`（Secrets：`DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_SSH_KEY` 等）。
4. 验证：公网 `https://你的域名/health`；把地址写入本仓 `config/public.json` 的 `cloudUrl`。
5. 套餐：控制台「套餐」内开通；开发默认 `PAYMENT_MODE=mock`。档位见 `services/cloud/src/plans.ts`（免费 3 仓 / 基础 ¥9.9·10 仓 / 专业 ¥29·30 仓）。

### 场景 D（可选）：打 Windows 安装包

1. 将 `config/public.json` 的 `cloudUrl` 改为正式 Cloud 地址（不要用 `127.0.0.1`）。
2. 仓库根：`pnpm package:win`
3. 产物：`release/electron/LabHub-Setup-0.1.0.exe`
4. 验证：安装后双击 LabHub，窗口内登录；清单与克隆在用户数据目录（默认 `%LOCALAPPDATA%\LabHubData`）。用户机需已装 Git。

## 8. 入口与关键流程

### 8.1 应用入口

- 本机进程：`server/src/index.ts`（`PORT` 默认 8790）
- 控制台：`client/src/main.ts` → `App.vue`；开发代理 `/api` → `:8790`
- Electron：根 `package.json` 的 `"main": "desktop/main.mjs"`
- Cloud：`services/cloud/src/index.ts`（默认 8780）

### 8.2 主流程

**流程 A：添加仓库并首次分析**

1. 用户登录 → 本机保存 Cloud JWT/会话
2. `POST /api/projects` 浅克隆到 `projects/<id>/`，写入 `data/projects.json`
3. 若已登录且有 AI 配额：经 Cloud `POST /v1/analyze` 生成分析文档；否则启发式本地生成
4. 清单元数据可同步到 Cloud `PUT /v1/catalog`（不含源码）

**流程 B：按模式启停**

1. 控制台选择 `profileId` → `POST /api/projects/:id/start`
2. `process-manager` 在项目 cwd 执行命令；可选注入 `runPort`
3. 运行态写入内存/runtime；日志可读；探测 `runtimeUrls`
4. `POST .../stop` 结束对应进程

**流程 C：`pnpm dev` 一体启动**

1. `scripts/ensure-cloud-dev.mjs` 补 `.env`、起 Postgres、等 `:5433`
2. concurrently 启动 server、client、cloud、`electron .`
3. Electron 开发态加载 `http://127.0.0.1:5177/`

## 11. 工程约定

- 代码组织：pnpm workspace；server/cloud 用 ESM + tsx；client 为 Vue SFC（当前以 `App.vue` 单体为主）。

## 12. 风险、债与未知

- **任意命令执行**：启动/构建/自定义命令在本机 shell 执行，仅适合受信环境，勿对公网开放 `:8790`。
- **端口冲突**：多托管仓常共用 `3000`/`5173` 等；依赖 `runPort` 或只启一端。
- **控制台体量**：`client/src/App.vue` 超大，后续改动易冲突，可考虑拆组件（技术债）。
- **支付**：生产 `PAYMENT_MODE=live` 真实渠道未在仓库完整落地。
- **analysis-relay**：遗留，易与 Cloud 争 `:8780`，默认勿启。
- **文档路径**：README 写安装包数据在 `%LOCALAPPDATA%\LabHub`，Electron 默认解析为 `LabHubData`；以安装时选定目录 / 注册表为准。
- 仓库中未能确认：正式许可证、系统化自动化测试覆盖范围。

## 13. 新人上手路径

1. 阅读：根 `README.md`、本文、`services/cloud/README.md`。
2. 先完成「场景 A」：`pnpm install` → `pnpm dev` → 用开发账号登录控制台。
3. 用「添加仓库」挂一个小仓，配置一个启动模式并看日志。
4. 小改动建议：改 `client/src/App.vue` 某一文案或 `server/src/routes/projects.ts` 某响应字段，热重载验证。
5. 若做 Cloud 运维：再读场景 C 与 GitHub Secrets 配置。
